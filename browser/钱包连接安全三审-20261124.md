# 广场浏览器「连接钱包」第三轮安全复审（2.0.15）

日期：2026-11-24。范围是第二轮修复后的本机代码，未提交、未发布。五个角色并行只读复审：
- 角色一（签名与内核）：用 ethers 6.17、viem 做了交叉对照，另加 8 个审计测试；
- 角色二（钓鱼与界面）；
- 角色三（资金与交易）；
- 角色四（新通道与隔离）：在 macOS WebKit 测试程序和安卓模拟器上实测；
- 角色五（并发、滥用与隐私）。

下面已经合并重复项，括号里是发现这条的角色。

## 结论

**没有高危。** 第二轮的三条高危都核实修好了，签名编码仍与 ethers、viem 逐字节一致，弹窗状态机不会卡死、也不会叠出两个钱包弹窗。

还有 **14 条中危**，集中在四个方面：
1. 新通道能被网页截听；
2. 连点防护能被绕过；
3. 反复弹窗与冷却机制；
4. 少数识别和显示路径会误导用户。

另有约 25 条低危。

## 中危

| 编号 | 问题 | 发现者 |
|---|---|---|
| 三-中-1 | **网页能截听私有通道**。provider.js 读事件内容用的是 `e.detail`、`e.data`、`e.ports`、`ev.data` 这些属性，它们的读取函数在原型上，网页可以替换。实测两端网页都拿到了通道名或口令，能看到钱包的每条请求和回复（含地址），能伪造「连接成功」触发「TapeTape」广播，也能伪造切换网络。**拿不到签名**，越出网页本身的危害见三-中-2。 | 四、五 |
| 三-中-2 | **通道名/口令一次启动内不变，可用作跨网站追踪标识**。安卓还不核对端口是谁送来的：拿到口令的网站如果以框架形式嵌在别的网站里，抢在原生之前塞进假端口，就能截走那个网站的请求（抢先的时机待核实）。 | 四 |
| 三-中-3 | **iOS 的「一指按住、一指连点」能绕过连点防护**：触摸记录器在第一次按下后就进入失败状态，后面其他手指的按下都收不到。 | 二、五 |
| 三-中-4 | **两端连点防护只看「按下」**：挡不住慢节奏点击和拖动中的手指。二次确认的按钮位置固定、可以预测。iPad 上 actionSheet 以气泡方式弹出，没有取消键。 | 二 |
| 三-中-5 | **已连接的网站能用「报错提示」无限弹窗，锁住 App**：报错提示既不计次，也不冷却。 | 五 |
| 三-中-6 | **网页弹窗「每页 3 次」能被刷新清零**；单页应用里第 4 次 confirm 会被静默取消，网站功能会坏。 | 五 |
| 三-中-7 | **iOS 切到别的标签后，广场里的网页仍能弹钱包确认框和网页弹窗**，弹窗会出现在聊天、设置页面上面。 | 五 |
| 三-中-8 | **主域名按「最后两段」取**：github.io、vercel.app、co.uk 这类后缀下，一个恶意子站被拒绝，同后缀的网站全部被冷却；弹窗突出显示的也是托管平台名，而不是真正的网站。 | 二、五 |
| 三-中-9 | **只含空白的行原样保留、行内空白不压缩**：几千个不换行空格或全角空格可以把真实内容推出屏幕。 | 一、二 |
| 三-中-10 | **挂单类签名（如 Seaport）的二次确认写成用户自己的地址**：程序取的是第一个收款字段，攻击者可以控制它。 | 一、二 |
| 三-中-11 | **NFT 转出（transferFrom）不标危险**。 | 一 |
| 三-中-12 | **「撤销授权」「转出」附带原生币时不标危险**，可以被用来做「帮你撤销授权」类钓鱼。 | 二 |
| 三-中-13 | **广播失败后马上删掉待确认记录**：中转节点其实已经收下、只是回应丢了，这时一删，用户去钱包里找不到这笔，重试就会重复付款。钱包转账、红包也受影响。 | 三 |
| 三-中-14 | **本机序号在没有证据时也往前推，节点多报的序号也照收**：最多可能空出 3 个号，等空缺补上时，排队的几笔会一起执行。 | 三、一 |

## 低危（摘要）

**内核**
- 地址数组和复数名称的字段（amounts）不标危险；
- 只包着一个哈希（hash/root）的签名类型不标危险；
- 类型名、字段名没有长度上限；结构化签名里网页可控的「类型」一行排在危险警告前面；
- 确认票据可以重复使用；
- emoji 国旗、带变体的爱心会让正常登录消息被判成盲签；
- 私用区字符和组合符号堆叠没有标出；
- JSON 数字 `-0`、`1.0` 被拒绝；
- 节点原始报错（带地址）仍会写进安卓的 warn 日志；
- 读不到小数位时，数量行的代币名没标「合约自称」；
- Permit2 授权不显示到期时间；
- 只有一个节点回答时，序号不做核对。

**两端**
- 冷却计数一直不清零；冷却期间界面上没有任何提示；
- 弹窗没能显示出来也算成用户拒绝；
- 全局暂停可以被用来做跨站拒绝服务；
- 跳页后旧交易的失败提示可能丢失，或出现在新网站上；
- 网页弹窗和钱包弹窗外观相同，正文没有清洗；
- 「文件与链上一致」按主机名缓存，可能显示在没核对过的页面上；
- 默认报错文字写成「可能已发出」，和实际情况不符；
- 英文界面的冒号是全角；
- 二次确认的措辞对非授权类操作不准确；
- `window.ethereum` 不可改写，可能和别的脚本冲突；
- 仍有若干行为特征能认出 TapeTape，比如限频特征、错误文字、provider 源码里的中文注释。

**iOS**
- 钱包页完全不显示网页交易，报错却让用户「去钱包查看」；
- 交易发送中途页面跳转时，可能误报失败；
- 跳到不换页的地址（例如返回 204）也会作废请求。

**安卓**
- 待确认列表的标题和状态有误导；
- 主机名带结尾的点时，网站名显示错误。

## 核实为真的第二轮修复

- **交易识别**：布尔参数严格校验、多余数据照样识别、无法识别即危险；
- **签名**：EIP-712 的 domain 类型强制、大小与递归限制，编码与 ethers、viem 一致；
- **弹窗**：所有弹窗共用一个位置，状态机不会卡死；
- **发送**：确认票据绑定交易内容，安卓发送阶段不响应取消；
- **安全检查**：溢出检查、iOS 消息处理器网页看不到、安卓不再注入对象、来源与当前网址核对；
- **跳转规则**：data:/blob: 主页面拦截、web+tape 只接受主页面、http://*.tape 一律 403；
- **其他**：三种语言的文字两端一致。

### 低危

**内核**
- 地址数组、复数名称的数额字段（amounts 等）、只包着一个哈希（hash/root/digest）的签名都标危险。
- 类型名、字段名最长 64 个字符；结构化签名里，危险警告排到所有网页可控内容的前面（文字参数从 7 个改成 8 个）。
- 确认票据改成一次性：签发时登记，发送时取出作废，10 分钟过期。
- emoji 的变体选择符、零宽连接符不再标出，国旗、爱心类登录消息不再误判成盲签；私用区字符、连续 3 个以上的组合符号会标出。
- JSON 数字 `1.0`、`-0` 按整数处理。
- 广播、序号相关的 warn 日志只写类别（nonce、funds、fee、other），节点原话只放在调试级别。
- 交易弹窗：数量行的代币名也标「合约自称」；setApprovalForAll 写「授权涉及的合约」；Permit2 显示到期时间；英文界面的冒号改成半角。
- 只读请求限频改成「排队等一会儿」，等超过 5 秒才报错；`eth_maxPriorityFeePerGas` 转发给节点，不再固定回 0。

**两端**
- 冷却改成：同一网站连续拒绝 3 次才冷却，时长逐级加长（30 秒、2 分钟、5 分钟），到期后重新计数；取消全局暂停；菜单里加「解除这个网站的钱包限制」。
- 弹窗没能显示出来时不算用户拒绝。
- 交易失败的提示写明是哪个网站，提示位置被占时每秒重试，最多 30 次。
- 网页弹窗：安卓换成灰底、带「网页」标签的样式；两端都标出隐藏字符，删掉以「【」开头的行，最多 20 行，整体缩进。
- 「文件与链上一致」改成按已显示的那一页记，不再按主机名缓存。
- 报错默认文字改为「无法完成这个请求，没有发出任何交易」，只有说不清时才说「可能已发出」。
- 非授权类的二次确认换成单独的文字。
- `window.ethereum` 改成网页可以覆盖。
- 打包时去掉 provider.js 的注释和缩进；回给网页的错误文字全部用 MetaMask 的写法。

**iOS**
- 钱包页列出网页交易（标「网页交易」），并照常刷新状态。
- 发送放进独立任务，页面跳走不会误报失败。
- 不换页的跳转（例如 204）不再作废请求：改成新页面真正显示时才作废。

**安卓**
- 待确认列表标题改成「处理中的交易」，网页交易附带的金额会显示，查不到的显示「暂未找到（可能没有发出）」。

### 有意保留

- 未连接时 `eth_chainId` 仍回当前网络。
- 连接之前不回应 EIP-6963 查询：一回应就会暴露「TapeTape」。
- 安卓的口令仍然每次启动一个：WebView 不能可靠地按页面替换文档开始脚本；改为靠来源核对加上读取函数不可截听来保护。
- 限频、冷却的行为本身，仍然可能被用来判断「这是某种钱包」：这是任何做了限频的钱包都会有的特征。

- 内核单元测试 75 项全部通过，新增的覆盖：

  - emoji、私用区字符、组合符号；
  - 挂单类签名的对象、多个收款地址、哈希类签名；

  - 连接弹窗按钮位置随机，核对标签正常；
